## 1. Threat Overview & Scope

Machine learning-based ransomware detectors rely on behavioral and static indicators extracted during execution.
This document formalizes the attacker capabilities, operational budgets, and evasion constraints under an **asymmetric threat model** where adding benign artifacts is trivial, but removing core destructive behavior is structurally bounded.

---

## 2. Attacker Profile & Goals

- **Objective:** Evade detection (force the classifier to predict $P(\text{ransomware}) < \theta$) while preserving full ransomware execution capability (encrypting user files and displaying ransom instructions).
- **Attacker Knowledge Levels:**
  - **Black-box:** Attacker queries the endpoint model or API (`predict()`), observing only verdicts or confidence scores.
  - **White-box / Surrogate:** Attacker has access to public datasets (MLRan / RanSMAP) and trains a surrogate model (e.g. Logistic Regression or LightGBM) to guide gradient-based evasion.

---

## 3. Asymmetric Attacker Capabilities

Not all features are equally mutable. In binary and behavioral feature spaces:

| Feature Category | Attacker Mutation Cost | Operational Feasibility | Examples |
|---|---|---|---|
| **Benign String Injection** | **Zero Cost** | Trivial (embed static text in PE binary) | Embedding MS-DOS stubs, open-source license headers, copyright strings. |
| **Benign API Padding** | **Very Low** | Trivial (insert dead/dummy API calls) | Calling `GetSystemDirectoryA`, `GetCursorPos`, `RegOpenKeyExA` on standard keys. |
| **Benign Registry Reads** | **Very Low** | Trivial (read non-existent or standard keys) | Reading standard Windows Explorer or Delphi locale registry paths. |
| **Malicious Signature Removal** | **Medium to High** | Difficult | Omitting anti-sandbox checks (`antisandbox_foregroundwindows`) or RWX memory allocations. |
| **I/O Write Entropy Removal** | **Impossible** | Prohibitive | Encrypted ciphertext intrinsically possesses maximal information entropy ($H \approx 8.0$ bits/byte). Cannot be masked without altering ciphertext. |
| **Bulk File I/O Suppression** | **High** | Difficult | An attacker can delay writes (slow ransomware), but must eventually write encrypted bytes to disk to accomplish extortion. |

## 4. Evaluated Attack Vectors (Feature-Space Only)

All attacks operate on feature vectors $\mathbf{x} \in \mathbb{R}^{483}$ subject to a perturbation budget $B$:

1. **Random Bit-Flip Attack:** Randomly flips up to $B$ features (0 -> 1 or 1 -> 0) to evaluate baseline stochastic resilience.
2. **Benign Feature Padding (Mimicry Attack):** Attacker identifies top features prevalent in goodware (e.g. compiler stubs, standard DLL loads) and sets them from $0 \to 1$ up to budget $B$.
3. **Top SHAP Suppression Attack:** Attacker removes the top-$k$ ransomware features with highest positive SHAP weights that are not strictly essential for file encryption.
4. **Gradient-Guided Greedy Attack:** Attacker perturbs feature vectors in the direction of the negative gradient of the loss function:
   $$\mathbf{x}' = \mathbf{x} - \epsilon \cdot \text{sign}(\nabla_{\mathbf{x}} \mathcal{L}(f(\mathbf{x}), y))$$
   projected onto the valid binary feature domain $\{0, 1\}^{483}$.

---

## 5. Defense & Hardening Strategies (T-P7-03)

1. **Adversarial Training:** Injecting perturbed training samples generated by mimicry and gradient attacks into training iterations.
2. **Robust Feature Subsetting:** De-weighting or pruning easily spoofable features (e.g. static PE strings like `STRING:!this program cannot be run in dos mode.`) from the primary linear decision boundary.
3. **Monotonic Constraints:** Enforcing that observing definitive malicious behavior (high write entropy, memory injection) monotonically increases the ransomware score, regardless of how many benign API calls are padded.
